# UI 디자인 가이드

## 디자인 원칙
1. Money Snap은 금융 관리 앱보다 가벼운 소비 스냅 앱처럼 보여야 한다.
2. 화면은 흰색 기반의 넓은 여백, 큰 사진 오브젝트, 짧은 텍스트, 명확한 액션으로 구성한다.
3. 사용자가 설명을 읽지 않아도 사진, 크기, 위치, 탭 구조만으로 흐름을 이해할 수 있어야 한다.
4. 모든 화면은 한 번에 확정하지 않고, 현재 홈 화면의 디자인 정책을 기준으로 한 화면씩 제작하고 피드백으로 수정한다.
5. Figma의 `03 DesignKit`은 레퍼런스이며, 실제 사용 규칙을 가진 컴포넌트는 `02 Components`에 정리한다.

## 컴포넌트
### 카드
```
카드는 반복 목록, 그룹 항목, 모달에만 사용한다.
페이지 섹션 전체를 카드처럼 감싸지 않는다.
기본 반경은 8~16px 범위에서 용도에 맞게 사용한다.
```

### 버튼
```
Primary: dark pill, white text, icon + short label
Secondary: light pill, dark text
Icon: iOS/SF Symbol 또는 02 Components의 아이콘 인스턴스 사용
```

### 입력 필드
```
가격 입력을 제외하면 키보드 입력을 최소화한다.
카테고리, 그룹, 공개 설정은 칩/리스트/토글 선택으로 처리한다.
```

### Figma 컴포넌트 운영
- `03 DesignKit`에서 가져온 iOS 상태바, 디바이스 프레임, 탭바는 `02 Components`로 옮긴 뒤 사용한다.
- 실제 화면에는 `02 Components`의 컴포넌트 인스턴스를 배치한다.
- 텍스트는 컴포넌트 위에 새로 덮지 않고, 가능한 경우 컴포넌트의 text property를 직접 수정한다.
- 홈과 이후 화면은 같은 iPhone 프레임, 상태바, 하단 탭바 규칙을 공유한다.

## 레이아웃
- 모바일 기준 프레임: iPhone 393x852
- 정렬: 상단 정보는 좌측, 핵심 오브젝트와 주요 액션은 중앙
- 간격: 헤더/캔버스/액션/요약/탭바가 서로 겹치지 않도록 고정 여백을 둔다
- 하단 탭바 위에는 최소 8px 이상의 시각적 여유를 둔다

## Motion / Interaction
### Home Canvas Physics
- 홈의 소비 오브젝트는 정적인 카드가 아니라 캔버스 위 물체처럼 동작한다.
- 새 소비가 추가되면 화면 상단에서 떨어지고, 기존 소비 오브젝트와 부딪히며 자연스럽게 자리를 잡는다.
- `기록하기` 버튼은 고정된 중심 액션으로 유지하고, 물리 오브젝트와 겹치지 않는다.
- 금액이 클수록 소비 오브젝트와 가격 태그의 시각적 크기가 커진다.
- 소비 오브젝트는 약간의 회전, 튕김, 충돌감을 가질 수 있지만 기록 흐름을 방해하지 않아야 한다.

### Swipe / Page Control
- 홈 캔버스가 여러 상태를 가질 때는 작은 페이지 인디케이터로 스와이프 가능성을 표현한다.
- 인디케이터는 기능 설명 텍스트를 붙이지 않고, 현재 위치와 다음 화면 존재만 알려준다.
- 기본 홈은 나의 소비 캔버스이며, 그룹 소비 캔버스는 같은 구조의 다음 페이지로 전환된다.
- 홈 스와이프는 그룹 Snap을 빠르게 훑어보는 기능이다. 그룹 목록/관리 역할은 그룹 탭에서 처리한다.

### Add Bottom Sheet
- 등록 플로우는 전체 화면 폼이 아니라 홈 위에 뜨는 단계형 바텀시트로 처리한다.
- 사진이 있는 기록에서는 카테고리와 가격 바텀시트 상단에 현재 사진 미리보기와 진행 상태를 보여준다.
- 여러 장을 선택한 경우 `1/3` 같은 진행 표시와 작은 다음 사진 썸네일을 사용한다.
- 사진 없음으로 기록하는 경우 이미지 미리보기 영역은 숨기거나 기본 오브젝트로 대체한다.
- 1단계는 카테고리 선택이다. 8개 내외의 아이콘 그리드 또는 리스트를 보여주고, 아이콘 아래나 옆에는 짧은 카테고리명을 둔다.
- 카테고리 아이콘은 색상 면을 남용하지 않는다. 기본은 무채색 라인 아이콘, 연한 중립 배경, 선택 상태의 얇은 테두리로 처리한다.
- `기타`의 더보기 아이콘은 컨테이너 중앙에 정렬한다. 임시 텍스트 기호처럼 어긋난 아이콘은 사용하지 않는다.
- 카테고리를 선택하면 같은 바텀시트 안에서 가격 입력 단계로 전환된다.
- 가격 입력 단계에는 선택한 카테고리 칩과 뒤로 액션을 둔다. 사용자는 뒤로 가서 카테고리를 다시 고를 수 있다.
- 가격 입력 완료 시 별도 확인 화면 없이 바로 저장하고 홈 캔버스에 반영한다.
- 여러 장을 선택한 경우 현재 사진 저장이 끝나면 같은 바텀시트가 다음 사진의 카테고리 선택 상태로 이어진다.
- 바텀시트 안에는 설명 문장을 길게 넣지 않는다. 단계 제목, 선택지, 주요 액션만 남긴다.
- 그룹 선택과 금액 공개 여부는 등록 바텀시트 안에 넣지 않는다.

### Snap Detail
- Snap 상세는 확인, 가격 수정, 카테고리 수정, 삭제만 담당한다.
- 사진 교체, 공유 그룹 변경, 금액 공개 설정 변경은 Snap 상세에 넣지 않는다.
- 수정 액션은 별도 복잡한 폼보다 작은 바텀시트나 인라인 선택으로 처리한다.
- 삭제는 명확한 위험 액션으로 두되, 화면의 중심 액션처럼 보이게 만들지 않는다.

### Group Snap Canvas
- 그룹 상세의 중심은 그룹 전체 금액이나 개별 Snap 리스트가 아니라 사람별 대표 Snap 오브젝트다.
- 각 사람별 오브젝트는 최신 소비 이미지, 프로필 이미지, 하단 정보 태그, 상세 진입 액션으로 구성한다.
- 하단 정보 태그에는 공개 설정에 따른 오늘 총액, 유저 이름, 오늘 Snap 개수를 한 곳에 모아 보여준다.
- 좌상단은 이름 배지가 아니라 프로필 이미지 자리로 사용한다. 프로필 이미지가 없으면 이니셜 기반 기본 프로필을 보여준다.
- 사람별 오브젝트의 좌하단에는 해당 유저의 오늘 Snap 상세로 들어가는 작은 화살표 액션을 둔다.
- 우상단 Snap 개수 배지는 사용하지 않는다. 이름과 Snap 개수를 여러 위치에 중복 표시하지 않는다.
- 공개 그룹에서는 사람별 오늘 총액 기준으로 오브젝트 크기를 다르게 표시할 수 있다.
- 비공개 그룹에서는 총액을 숨기고 총액 기준 크기 차이도 사용하지 않는다. 대신 동일 크기 또는 Snap 개수 중심의 가벼운 차이만 사용한다.
- 그룹 전체 총액은 필요할 경우 작은 pill이나 보조 텍스트로만 표시한다.
- 그룹 상세 하단에는 `오늘 올라온 Snap` 같은 개별 Snap 리스트를 중복으로 두지 않는다.
- 그룹 상세 화면이 공동 가계부, 정산, 랭킹 화면처럼 보이지 않게 한다.

### Constraints
- 오브젝트는 상단 헤더, `기록하기` 버튼, 총액 영역, 하단 탭바와 겹치지 않는다.
- 새 오브젝트의 낙하 및 안정화는 약 0.6~1.2초 안에 끝나는 것을 목표로 한다.
- 과도한 애니메이션, 긴 대기 시간, 반복적인 효과음/시각 효과는 피한다.
- 접근성 설정에서 모션 감소가 켜진 경우 낙하/충돌 애니메이션은 짧은 fade/scale 전환으로 대체한다.

## 애니메이션
- 소비 오브젝트 낙하/충돌: 0.6~1.2s
- 화면 전환: iOS 기본 push/sheet 감각
- 버튼 피드백: 짧은 scale 또는 opacity
- 과도한 반복 애니메이션과 장식성 글로우는 금지

## 아이콘
- Figma에서는 iOS/SF Symbol 기반 컴포넌트를 우선 사용한다.
- 앱 구현 시에는 플랫폼 아이콘 또는 lucide 등 검증된 아이콘 라이브러리를 사용한다.
- 임시 텍스트 기호를 아이콘처럼 쓰지 않는다.
