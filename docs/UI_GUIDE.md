# UI 디자인 가이드

## 구현 기준 Figma

- 시각적 원본은 [Money Snap - Product Design](https://www.figma.com/design/IDNeYlc3584NY9YhsyUQYE/Money-Snap---Product-Design?node-id=0-1&t=lW8FBJFfcXo3cHEC-1)이다.
- 구현 작업 항목마다 대상 frame node ID를 고정하고, 해당 node의 design context·스크린샷·원본 asset을 다시 조회한 뒤 SwiftUI로 변환한다.
- 기준 viewport는 393x852다. Figma의 기기 프레임과 가짜 상태바는 production asset으로 복제하지 않고 실제 iOS safe area와 system chrome을 사용한다.
- 현재 확인한 핵심 frame은 홈 `9:2`, 그룹 목록 `75:86`, 그룹 Snap 상세 `77:163`, 그룹 생성 `77:480`, 지출 상세 수정 `77:582`, 보관함 달력 `77:681`, 마이 `77:798`, 금액 입력 완료 `153:4156`이다.
- Figma가 내보내는 React/Tailwind 코드는 수치·자산·계층을 확인하는 참고 자료다. production 구현은 SwiftUI 컴포넌트와 프로젝트의 디자인 토큰으로 작성한다.
- Figma asset URL은 만료될 수 있으므로 화면 구현 시작 시 원본을 내려받아 `Assets.xcassets`에 보존하고 source node ID를 manifest에 기록한다.

## 시각 정합성 완료 조건

- 공통 색상, 글꼴, 간격, 모서리, 그림자와 tab/sheet 표현을 `MoneySnapVisualSystem`에 모으고 실제 반복이 확인된 항목만 토큰으로 승격한다.
- 화면별 고정 fixture를 사용해 393x852 SwiftUI snapshot을 만들고 Figma reference와 overlay/diff로 비교한다.
- 글꼴·OS 렌더링 차이를 고려한 허용치는 첫 baseline 작업에서 수치로 고정한다. 차이가 발생하면 원인을 리뷰하며 baseline을 자동 갱신하지 않는다.
- 전체 흐름은 지정된 iOS Simulator/OS에서 별도 screenshot과 XCUITest로 확인한다.
- Figma와 다른 결과가 필요한 경우 구현 편의로 임의 변경하지 않고 디자인 문서나 사용자 결정부터 갱신한다.

## 디자인 원칙
1. Money Snap은 금융 관리 앱보다 가벼운 소비 스냅 앱처럼 보여야 한다.
2. 화면은 흰색 기반의 넓은 여백, 큰 사진 오브젝트, 짧은 텍스트, 명확한 액션으로 구성한다.
3. 사용자가 설명을 읽지 않아도 사진, 크기, 위치, 탭 구조만으로 흐름을 이해할 수 있어야 한다.
4. 모든 화면은 한 번에 확정하지 않고, 현재 홈 화면의 디자인 정책을 기준으로 한 화면씩 제작하고 피드백으로 수정한다.
5. Figma의 `03 DesignKit`은 레퍼런스이며, 실제 사용 규칙을 가진 컴포넌트는 `02 Components`에 정리한다.

## 컴포넌트
### 카드
```
카드는 반복 목록, 그룹 항목, 모달에만 사용한다.
페이지 섹션 전체를 카드처럼 감싸지 않는다.
기본 반경은 8~16px 범위에서 용도에 맞게 사용한다.
```

### 버튼
```
Primary: dark pill, white text, icon + short label
Secondary: light pill, dark text
Icon: iOS/SF Symbol 또는 02 Components의 아이콘 인스턴스 사용
```

### 입력 필드
```
가격 입력을 제외하면 키보드 입력을 최소화한다.
카테고리, 그룹, 공개 설정은 칩/리스트/토글 선택으로 처리한다.
```

### Figma 컴포넌트 운영
- `03 DesignKit`에서 가져온 iOS 상태바, 디바이스 프레임, 탭바는 `02 Components`로 옮긴 뒤 사용한다.
- 실제 화면에는 `02 Components`의 컴포넌트 인스턴스를 배치한다.
- 텍스트는 컴포넌트 위에 새로 덮지 않고, 가능한 경우 컴포넌트의 text property를 직접 수정한다.
- 홈과 이후 화면은 같은 iPhone 프레임, 상태바, 하단 탭바 규칙을 공유한다.
- SF Symbol로 지정된 아이콘은 가능한 한 동일한 system name을 사용하고, Figma 원본 asset이 있는 이미지는 임의 대체 아이콘을 만들지 않는다.

## Motion / Interaction

### Authentication and account
- 로그인 화면은 Figma의 해당 frame을 기준으로 구현하고 Sign in with Apple 단일 액션만 둔다.
- 유효한 session을 복구하는 동안 로그인 화면을 잠깐 노출했다가 홈으로 전환하는 깜빡임을 만들지 않는다.
- 로그아웃과 계정 탈퇴를 같은 의미로 보이게 하지 않는다. 탈퇴는 설명과 재인증, 최종 확인이 있는 위험 액션으로 둔다.
- MVP에서는 알림 권한 사전 안내, 시스템 권한 prompt와 알림 시간 설정 화면을 만들지 않는다.
- Apple 이름을 사용할 수 없으면 `MoneySnap 사용자`를 표시한다. MVP에는 이름 편집과 profile 사진 업로드를 두지 않는다.
- 기본 avatar는 display name의 첫 grapheme를 쓰고 사용할 수 없으면 MoneySnap mark를 쓴다. 임의의 user ID 접미사를 이름이나 avatar로 노출하지 않는다.
- My의 `내 그룹 관리`는 그룹 목록·만들기·초대 가입을 연다. `도움말`은 기록·공유·그룹·보관함 사용 가이드를 연다. `앱 설정`은 로그아웃과 계정 탈퇴를 연다.
- 홈·보관함·마이 오른쪽 원형 메뉴 버튼은 사이드바를 연다. 사이드바에서 홈·그룹·보관함·마이와 도움말로 이동한다.

### Home Canvas Physics
- 홈의 소비 오브젝트는 정적인 카드가 아니라 캔버스 위 물체처럼 동작한다. 라이브 Home은 SpriteKit 무중력 유영을 쓰고, Figma `9:2` visual 시나리오와 모션 감소는 정적 rest 3장 좌표를 유지한다.
- 라이브 물리는 `기록하기` 버튼 위 영역에서만 동작한다. SpriteKit physics body는 쓰지 않고 p5 Bouncy Bubbles처럼 위치와 속도를 직접 적분한다. 겹치면 반지름 합까지 밀어낸 뒤 튕기고, 벽에 닿으면 그 축만 뒤집는다. 거의 멈췄을 때만 느린 순항 속도를 다시 넣는다.
- `기록하기` 버튼은 탭바 추가와 겹치지 않게 약 80% 크기의 고정 중심 액션으로 두고, 물리 바닥은 버튼 상단보다 위에 둔다.
- 금액이 클수록 소비 오브젝트와 가격 태그의 시각적 크기가 커지되, 라이브 박스 한 변은 약 44...97pt로 읽히게 둔다. 사진이 있는 오브젝트와 category placeholder 모두 같은 금액 비율을 따른다.
- 금액 비공개 그룹 캔버스는 금액 티켓과 `비공개` 문구를 그리지 않고 이미지만 보여 준다. 이미지 크기는 금액에 묶지 않는다.
- 오늘 기록이 없어도 Home은 empty-state 문구로 바뀌지 않는다. 같은 캔버스 chrome을 유지하고 `오늘 총 소비`는 `₩0`이다.
- `오늘 소비` 목록은 오늘의 모든 개인 Snap이다. 2열 150×46 행을 아래로 이어 붙이고, 첫 화면 아래 건은 세로 스크롤로 본다. Figma `9:2` visual은 2건 고정을 유지한다.
- 연결된 사진은 Home featured/recent와 Snap 상세에 JPEG로 표시한다. 번들 fixture artwork는 visual 시나리오 전용이다.
- 소비 오브젝트는 약간의 회전, 튕김, 충돌감을 가질 수 있지만 기록 흐름을 방해하지 않아야 한다.

### Swipe / Page Control
- 홈 캔버스가 여러 상태를 가질 때는 작은 페이지 인디케이터로 스와이프 가능성을 표현한다.
- 인디케이터는 기능 설명 텍스트를 붙이지 않고, 현재 위치와 다음 화면 존재만 알려준다.
- 기본 홈은 나의 소비 캔버스이며, 그룹 소비 캔버스는 같은 구조의 다음 페이지로 전환된다.
- 홈 스와이프는 그룹 Snap을 빠르게 훑어보는 기능이다. 페이지 순서는 내 그룹 목록에서 바꾸고, 그룹 목록/관리 역할은 그룹 탭에서 처리한다.

### Add Bottom Sheet
- 등록 플로우는 홈 위에 올라오는 바텀시트로 처리한다. 사진 시작 화면은 Figma `86:716`처럼 카메라 뷰파인더 구성이다. 하단 왼쪽은 앨범, 가운데는 셔터, 오른쪽은 `없음`이며 선택 리스트처럼 보이지 않게 한다. 카테고리+금액은 large detent로 화면을 더 채운다. Figma staged 카테고리/금액 시트는 visual CI만 기존 높이를 유지한다.
- 시작 quick action은 카메라 1장, 앨범 최대 3장, 사진 없음이다. 카메라 권한은 셔터를 누를 때만 요청하고 거부·미지원이면 앨범과 사진 없음으로 돌아온다.
- 사진 선택 다음 라이브 시트는 카테고리와 금액을 한 화면에서 입력한다. 카테고리를 고르기 전에는 `카테고리를 선택하세요`를 보여 준다. 카테고리 그리드를 금액 키패드 위에 둔다.
- 사진 미리보기는 시트 중앙의 큰 정사각이다.
- 키패드는 숫자와 `C`(금액 초기화)·지움만 두고, 완료/다음은 키패드 아래 별도 버튼이다. 저장 중에도 버튼 문구를 `저장 중`으로 바꾸지 않는다.
- 여러 장을 입력할 때 다음 사진으로 넘어가면 카테고리와 금액을 비운다.
- Figma `108:465` 카테고리 단계와 `108:549` 금액 단계는 visual CI 원본으로 유지한다. 라이브 UX는 결합 시트가 우선한다.
- 사진이 있는 기록에서는 결합 시트 상단에 현재 사진 미리보기와 진행 상태를 보여준다.
- 여러 장을 선택한 경우 `1/3` 같은 진행 표시와 작은 다음 사진 썸네일을 사용한다.
- 사진 없음으로 기록하는 경우 이미지 미리보기 영역은 숨기거나 선택 category의 고정 icon/color placeholder로 대체한다. 같은 category placeholder를 금액에 따라 키우거나 색·모양을 바꾸지 않는다.
- 카테고리는 8개 내외의 아이콘 그리드다. 아이콘 아래나 옆에는 짧은 카테고리명을 둔다.
- 카테고리 아이콘은 색상 면을 남용하지 않는다. 기본은 무채색 라인 아이콘, 연한 중립 배경, 선택 상태의 얇은 테두리로 처리한다.
- `기타`의 더보기 아이콘은 컨테이너 중앙에 정렬한다. 임시 텍스트 기호처럼 어긋난 아이콘은 사용하지 않는다.
- 한 장 또는 마지막 사진은 `완료`로 저장하고 별도 확인 화면 없이 홈 캔버스에 반영한다.
- 여러 장을 선택해 다음 사진이 남아 있으면 금액 입력 액션을 `다음`으로 표시한다. 현재 사진을 저장한 뒤 같은 결합 시트가 다음 사진 입력으로 이어진다.
- 여러 장은 하나의 carousel record가 아니라 사진마다 별도 Snap으로 저장하며 한 Snap에는 active image 한 장만 표시한다.
- 사진을 고른 시점부터 JPEG publish를 시작하고, 저장 확인은 record 응답을 기다린다.
- 라이브 시트는 아래로 내려 닫을 수 있다. 아직 저장하지 않은 현재 입력만 취소하고 이전에 저장한 사진은 유지한다.
- 바텀시트 안에는 설명 문장을 길게 넣지 않는다. 단계 제목, 선택지, 주요 액션만 남긴다.
- 그룹 선택과 금액 공개 여부는 등록 바텀시트 안에 넣지 않는다.

### Save 이후 Share
- 개인 save 성공과 Home 반영을 먼저 끝낸 뒤, 사용자가 속한 그룹이 있을 때만 해당 Snap에 비차단 share action을 보인다.
- share action은 group 선택 sheet를 열고 현재 Snap 한 건과 group 한 곳만 선택한다. multi-Snap·multi-group checkbox UI는 만들지 않는다.
- sheet dismiss, 건너뛰기와 실패는 성공한 개인 save를 되돌리지 않는다. 실패 상태는 Home의 같은 Snap에서 명시적으로 재시도할 수 있게 한다.
- 선택한 group의 금액 공개 여부를 sheet에 짧게 표시하고 기록마다 공개 여부를 바꾸는 control은 두지 않는다.

### Archive Calendar
- 보관함은 Figma `77:681` 월 달력이다. Home/My와 같은 타이틀 크롬을 쓴다. 제목은 `Archive`, 부제는 현재 월이다.
- 달력은 일요일부터 시작하는 7열이다. 1일은 그 요일 칸에 놓는다.
- 월 이동은 `이전 달`/`다음 달` 텍스트가 아니라 44pt 원형 chevron이다.
- 기록이 있는 날은 날짜 아래 작은 점으로 표시하고, 선택한 날은 navy 원과 흰 숫자로 표시한다.
- 선택 날짜의 개인 Snap만 아래에 보여 준다. 월 전체 빈 상태와 선택 날짜 빈 상태는 다른 문구를 쓴다.
- 시스템 `List`나 가계부형 숫자표로 보이지 않게 하고, Home 최근 행과 같은 사진·카테고리·금액 행을 쓴다.

### Snap Detail
- Snap 상세는 확인, 가격 수정, 카테고리 수정, 삭제만 담당한다.
- 사진 교체, 공유 그룹 변경, 금액 공개 설정 변경은 Snap 상세에 넣지 않는다.
- 수정 액션은 별도 복잡한 폼보다 작은 바텀시트나 인라인 선택으로 처리한다.
- 삭제는 명확한 위험 액션으로 두되, 화면의 중심 액션처럼 보이게 만들지 않는다.

### Group Snap Canvas
- 그룹 상세의 중심은 그룹 전체 금액이나 개별 Snap 리스트가 아니라 사람별 대표 Snap 오브젝트다.
- 각 사람별 오브젝트는 해당 날짜의 `sharedAt` 기준 최신 소비 이미지 또는 고정 category placeholder, 기본 avatar, 하단 정보 태그, 상세 진입 액션으로 구성한다.
- 하단 정보 태그에는 공개 설정에 따른 오늘 총액, 유저 이름, 오늘 Snap 개수를 한 곳에 모아 보여준다.
- 좌상단은 이름 배지가 아니라 기본 avatar 자리로 사용한다. MVP에는 profile 사진 업로드가 없으므로 display name의 첫 grapheme 또는 MoneySnap mark를 보여준다.
- 사람별 오브젝트의 좌하단에는 해당 유저의 오늘 Snap 상세로 들어가는 작은 화살표 액션을 둔다.
- 우상단 Snap 개수 배지는 사용하지 않는다. 이름과 Snap 개수를 여러 위치에 중복 표시하지 않는다.
- 공개 그룹에서는 사람별 오늘 총액 기준으로 오브젝트 크기를 다르게 표시할 수 있다.
- 비공개 그룹에서는 총액을 숨기고 총액 기준 크기·정렬 차이도 사용하지 않는다. 동일한 크기·순서 또는 금액과 무관한 Snap 개수 중심의 가벼운 신호만 사용한다.
- 그룹 전체 총액은 필요할 경우 작은 pill이나 보조 텍스트로만 표시한다.
- 그룹 상세 하단에는 `오늘 올라온 Snap` 같은 개별 Snap 리스트를 중복으로 두지 않는다.
- 그룹 상세 화면이 공동 가계부, 정산, 랭킹 화면처럼 보이지 않게 한다.

### Group Create and Join
- 생성 화면은 trim 후 1~30 grapheme cluster group name과 공개/비공개 두 선택만 핵심 입력으로 둔다.
- 금액 공개 여부는 생성 이후 바꿀 수 있는 설정처럼 표현하지 않는다.
- 초대 가입 확인은 group name과 금액 공개 여부를 가입 action보다 먼저 보여준다.
- 만료·폐기·정원 초과는 긴 정책 설명 대신 명확한 실패 상태와 닫기/재시도 action으로 표현한다.
- owner와 member의 액션을 구분한다. member는 탈퇴, owner는 member 제거와 그룹 삭제를 볼 수 있으며 owner 탈퇴·role 양도 UI는 만들지 않는다.

### Constraints
- 오브젝트는 상단 헤더, `기록하기` 버튼, 총액 영역, 하단 탭바와 겹치지 않는다.
- 새 오브젝트의 낙하 및 안정화는 약 0.6~1.2초 안에 끝나는 것을 목표로 한다.
- 과도한 애니메이션, 긴 대기 시간, 반복적인 효과음/시각 효과는 피한다.
- 접근성 설정에서 모션 감소가 켜진 경우 낙하/충돌 애니메이션은 짧은 fade/scale 전환으로 대체한다.

## 애니메이션
- 소비 오브젝트 낙하/충돌: 0.6~1.2s
- 화면 전환: iOS 기본 push/sheet 감각
- 버튼 피드백: 짧은 scale 또는 opacity
- 과도한 반복 애니메이션과 장식성 글로우는 금지

## 아이콘
- Figma에서는 iOS/SF Symbol 기반 컴포넌트를 우선 사용한다.
- 앱 구현 시에는 플랫폼 아이콘 또는 lucide 등 검증된 아이콘 라이브러리를 사용한다.
- 임시 텍스트 기호를 아이콘처럼 쓰지 않는다.
