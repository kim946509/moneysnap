# Money Snap 핵심 사용자 흐름

## 목적

이 문서는 Money Snap의 핵심 사용자 흐름을 정의한다. 시각 디자인의 세부 스타일을 정하는 문서가 아니라, 사용자가 앱을 어떻게 시작하고, 소비를 어떻게 기록하며, 언제 개인 기록과 그룹 공유를 선택하는지 정하는 기준 문서다.

UI/UX 관점은 이 단계부터 고려한다. 단, 여기서 결정할 것은 색상, 폰트, 카드 모양 같은 시각 상세가 아니라 **사용자가 어느 순간에 고민하고, 어느 순간에 바로 끝낼 수 있어야 하는가**이다.

## 흐름 원칙

- 첫 실행에서 Sign in with Apple로 로그인하고 유효한 Money Snap session이 있으면 로그인 화면을 건너뛴다.
- 홈은 오늘의 소비 캔버스다.
- 사용자는 홈에서 바로 소비를 기록할 수 있어야 한다.
- 기록은 카메라 1장, 앨범 최대 3장 또는 사진 없음 중 하나를 고른 뒤 카테고리 선택과 금액 입력을 단계형 바텀시트에서 끝내는 짧은 흐름이어야 한다.
- 사진을 여러 장 선택한 경우에는 한 장씩 카테고리와 금액을 입력해 각각 별도 개인 Snap으로 저장하고, `다음`을 누르면 다음 사진으로 넘어가야 한다.
- 소비는 저장 즉시 오늘의 소비 캔버스에 반영되어야 한다.
- 기본 저장 위치는 항상 나만 보기다.
- 그룹 공유는 사용자가 속한 그룹이 있을 때만 저장 이후 Home의 명시적 action으로 등장한다.
- 등록 흐름 안에서는 그룹을 선택하지 않는다.
- 금액 공개 여부는 기록할 때마다 선택하지 않고, 그룹 생성/참여 시 정해진 그룹 설정을 따른다.
- MVP에서는 알림 권한을 요청하거나 기록 리마인더를 보내지 않는다.

## 인증과 계정 흐름

```text
첫 실행 또는 session 만료
→ Sign in with Apple
→ 서버가 Apple credential 검증
→ Money Snap session 발급
→ 홈
```

유효한 refresh session은 Keychain에서 복구해 홈으로 바로 진입한다. access token 만료는 사용자에게 로그인 화면을 보여주기 전에 refresh로 복구한다. Apple credential 취소 또는 refresh 실패가 확정된 경우에만 로그인 화면으로 돌아간다.

로그아웃은 마이의 설정에서 실행하며 현재 기기 session만 종료한다. 계정 탈퇴는 같은 설정 화면에서 별도 위험 액션으로 제공한다. 탈퇴는 Sign in with Apple 재인증, 삭제 범위 안내, 명시적 확인, 서버 삭제와 Apple token revoke, 로컬 Keychain 삭제 순서로 진행한다. 삭제 실패 중에는 성공 화면이나 로그아웃 완료 상태로 가장하지 않는다.

Apple이 첫 로그인에서 유효한 이름을 제공하면 profile display name으로 사용하고, 제공하지 않으면 `MoneySnap 사용자`를 보여준다. MVP에서는 display name이나 profile 사진을 편집하지 않는다. 기본 avatar는 이름의 첫 grapheme 또는 MoneySnap mark다.

## 핵심 루프

Money Snap의 메인 루프는 다음과 같다.

1. 사용자는 홈에서 오늘의 소비 캔버스를 본다.
2. 사용자는 기록하기를 눌러 소비 사진 1장을 촬영하거나 앨범에서 최대 3장을 선택하거나 `사진 없음`을 고른다.
3. 사용자는 현재 사진 또는 category placeholder를 보면서 카테고리 선택 바텀시트에서 카테고리를 고른다.
4. 선택 즉시 같은 바텀시트가 가격 입력 단계로 전환된다.
5. 사용자는 가격을 입력한다. 남은 사진이 있으면 `다음`, 마지막 사진이면 `완료`를 누른다.
6. 현재 소비는 기본값인 나만 보기 Snap으로 먼저 durable save된다.
7. 남은 사진이 있으면 다음 사진이 나타나고 카테고리 선택 단계부터 반복한다.
8. 저장된 소비는 즉시 오늘의 소비 캔버스에 시각적으로 반영된다.
9. 사용자는 캔버스를 보며 오늘의 소비 흐름을 직관적으로 이해한다.
10. 속한 그룹이 있으면 저장된 Snap의 Home share action으로 group 하나를 선택할 수 있다. 건너뛰기·취소·실패는 개인 저장을 되돌리지 않는다.

## 기본 홈 흐름

홈은 리스트나 통계 화면이 아니라 오늘의 소비 캔버스다.

홈에서 사용자는 오늘 기록한 소비를 사진, 크기, 배치 중심으로 본다. 많이 쓴 소비는 더 크게 보이고, 적게 쓴 소비는 더 작게 보인다. 사용자는 숫자표를 읽지 않아도 오늘 어디에 돈이 크게 나갔는지 바로 이해할 수 있어야 한다.

홈의 핵심 행동은 기록하기다. 기록하기는 홈에서 가장 쉽게 접근할 수 있어야 하며, 사용자가 소비를 떠올린 순간 바로 시작할 수 있어야 한다.

## 소비 기록 흐름

### 1. 사진 선택

사용자는 기록하기를 누른 뒤 사진을 1장 촬영하거나 앨범에서 최대 3장을 선택하거나 사진 없이 기록한다. 카메라 권한은 촬영을 선택할 때만 요청하고, 거부되거나 기기가 지원하지 않으면 앨범과 사진 없음 선택으로 돌아갈 수 있어야 한다.

카메라·앨범을 고른 경우 사진 선택이 기록의 시각적 시작점이다. 사진 없음도 동등한 quick action이며 숫자표에서 시작하는 가계부처럼 보이지 않게 category 오브젝트와 단계형 입력을 사용한다.

사용자는 앨범에서 여러 이미지를 선택할 수 있다. 이 경우 Money Snap은 여러 필드를 한 번에 보여주는 대량 입력 화면을 만들지 않고, 현재 사진 한 장을 보여주며 카테고리와 금액을 입력하게 한다. 저장할 때마다 사진 한 장과 category·amount를 가진 별도 Snap이 생긴다.

사진 없이 기록하는 선택지도 제공한다. 사진이 없는 기록에서는 바텀시트 상단의 이미지 미리보기 영역을 숨기거나 선택 category의 고정 icon/color placeholder로 대체한다. 금액 때문에 placeholder의 색·크기·모양을 바꾸지 않는다.

### 2. 카테고리 선택

사진을 선택한 뒤 카테고리 선택 바텀시트가 나타난다.

사진이 있는 경우 바텀시트 상단에는 현재 입력 중인 사진과 진행 상태를 작게 보여준다. 예를 들어 여러 장 중 첫 번째라면 `1/3`처럼 표시해 사용자가 지금 어떤 사진을 입력하는지 알 수 있어야 한다.

카테고리는 소비를 이해하기 위한 최소 분류다. 카테고리 선택은 8개 내외의 아이콘 그리드로 제공하며, 사용자가 하나를 누르면 별도 다음 버튼 없이 가격 입력 단계로 전환된다.

권장 초기 카테고리는 다음과 같다.

- 식비
- 카페
- 교통
- 쇼핑
- 생활
- 문화
- 건강
- 기타

### 3. 금액 입력

카테고리를 선택하면 같은 바텀시트가 가격 입력 단계로 바뀐다.

가격 입력 단계에서도 현재 사진 미리보기와 진행 상태는 유지한다. 사용자는 가격을 입력하는 동안 이 금액이 어떤 사진에 해당하는지 헷갈리지 않아야 한다.

금액 입력은 빠르고 단순해야 한다. 이 단계에서 예산, 결제수단, 상세 메모 같은 추가 입력을 요구하지 않는다. 사용자는 뒤로 버튼으로 카테고리 선택 단계로 돌아갈 수 있어야 한다.

입력 가능한 금액은 `1...999,999,999 KRW` 정수다. 기록 날짜는 기기의 tzdb region time zone을 기준으로 서버가 current day 또는 직전 day만 받아들이며 저장 후에는 바꾸지 않는다. 사용자는 일반 흐름에서 이 validation 규칙을 설정으로 해석할 필요가 없다.

가격 입력 액션을 누르면 현재 소비가 바로 저장된다. 한 장 기록과 마지막 사진에서는 `완료`, 뒤에 사진이 남아 있으면 `다음`으로 표시한다.

여러 장을 선택한 경우 현재 사진 저장이 끝나면 다음 사진의 카테고리 선택 바텀시트로 바로 넘어간다. 마지막 사진까지 완료되면 홈 캔버스로 돌아간다.

바텀시트 바깥을 탭하거나 아래로 내려 닫으면 아직 저장하지 않은 현재 입력만 취소한다. 앞에서 이미 저장한 사진은 유지한다.

### 4. 저장

MVP 등록 바텀시트의 저장 기본값은 나만 보기다.

사용자가 속한 그룹이 있더라도 카테고리와 가격 입력 중에는 그룹 선택을 요구하지 않는다. 이유: 기록 도중 선택지가 늘어나면 단계형 입력의 가벼움이 깨진다.

그룹 공유는 Snap 상세의 수정 기능과 분리한다. 저장한 Snap의 Home share action을 사용자가 누르면 group 선택 sheet를 연다. 이 sheet는 현재 Snap 한 건을 group 한 곳에만 공유하며, 여러 Snap·여러 group을 동시에 고르는 UI를 제공하지 않는다. 다른 group에도 공유하려면 사용자가 action을 다시 실행한다.

금액 공개 여부는 기록 단계에서 별도로 묻지 않는다. 공유된 소비는 선택한 그룹의 공개 설정을 그대로 따른다.

share sheet를 건너뛰거나 닫고, 네트워크 또는 권한 문제로 공유가 실패해도 개인 Snap은 이미 저장된 상태를 유지한다. Home에서 명시적으로 재시도할 수 있으며 개인 save를 rollback하지 않는다.

### 5. 캔버스 반영

저장이 완료되면 사용자는 홈으로 돌아가고, 새 소비가 오늘의 소비 캔버스에 바로 나타난다.

이 즉시 반영이 기록의 보상이다. 사용자는 입력을 끝낸 직후 자신의 소비 캔버스가 변하는 것을 보며 기록의 재미를 느껴야 한다.

## 그룹이 없는 사용자 흐름

```text
홈 캔버스
→ 기록하기
→ 사진 촬영, 앨범 선택 또는 사진 없음
→ 카테고리 선택
→ 가격 입력
→ 자동 저장
→ 홈 캔버스에 즉시 반영
```

이 흐름은 Money Snap의 가장 가벼운 기본 경험이다. 사용자는 공유나 그룹을 몰라도 혼자서 충분히 앱을 사용할 수 있어야 한다.

## 그룹이 있는 사용자 흐름

```text
홈 캔버스
→ 기록하기
→ 사진 촬영, 앨범 선택 또는 사진 없음
→ 카테고리 선택
→ 가격 입력
→ 나만 보기로 저장
→ 홈 캔버스에 즉시 반영
→ 원할 때 해당 Snap의 공유 action
→ group 하나 선택 또는 건너뛰기
```

그룹이 있는 사용자에게도 등록 완료의 기본값은 나만 보기다. 그룹 공유는 저장 이후 Home의 별도 흐름으로 열어두되, 소비 기록 자체를 지연시키지 않는다.

## Snap 상세 흐름

Snap 상세는 기록을 복잡하게 관리하는 화면이 아니라, 이미 저장된 소비를 가볍게 확인하고 필요한 최소 수정만 하는 화면이다.

Snap 상세에서 제공하는 편집은 다음으로 제한한다.

- 카테고리 수정
- 가격 수정
- 삭제

사진 교체, 공유 그룹 변경, 금액 공개 설정 변경은 Snap 상세에서 다루지 않는다. 공유와 공개 설정은 그룹 정책과 별도 공유 흐름의 책임으로 분리한다.

## 여러 장 선택 흐름

```text
홈 캔버스
→ 기록하기
→ 앨범에서 여러 장 선택
→ 1번째 사진 미리보기
→ 카테고리 선택
→ 가격 입력
→ 1번째 사진 저장
→ 2번째 사진 미리보기
→ 카테고리 선택
→ 가격 입력
→ 마지막 사진까지 반복
→ 홈 캔버스에 즉시 반영
```

여러 장 선택은 빠른 연속 기록을 위한 기능이다. 한 화면에 여러 사진의 금액과 카테고리를 동시에 입력하게 만들지 않는다. 이유: 대량 편집표처럼 보이면 Money Snap의 가벼운 스냅 기록 감각이 약해진다.

## 홈 캔버스의 역할

홈 캔버스는 Money Snap의 정체성을 보여주는 첫 화면이다.

참고 방향은 Kit iOS 레퍼런스처럼 넓은 여백, 큰 시각 오브젝트, 장난기 있는 위젯형 구성, 하단 탭 기반 모바일 앱 감각이다. 단, Money Snap에서는 금융 관리 화면처럼 딱딱해지지 않도록 사진 기반 소비 오브젝트와 크기 차이를 핵심 시각 언어로 삼는다.

홈 캔버스는 다음 역할을 한다.

- 오늘의 소비를 한눈에 보여준다.
- 기록이 끝난 직후 변화가 보이는 보상 화면이 된다.
- 공유용 스냅샷의 원본이 된다.
- 사용자가 매일 돌아오는 메인 루프의 시작점이 된다.

홈은 기본적으로 나의 오늘 소비 캔버스를 보여준다. 사용자가 좌우로 스와이프하면 내가 속한 그룹의 오늘 Snap을 빠르게 볼 수 있다. 이 스와이프는 그룹 관리 기능이 아니라, 오늘의 그룹 소비 분위기를 가볍게 훑어보는 행동이다.

## 그룹 탭의 역할

그룹 탭은 홈의 스와이프와 다른 역할을 가진다.

홈 스와이프는 오늘의 Snap을 빠르게 보는 공간이고, 그룹 탭은 내가 속한 그룹을 찾고 관리하고 특정 그룹으로 진입하는 공간이다.

그룹 탭에서는 다음 흐름을 우선한다.

```text
그룹 탭
→ 내가 속한 그룹 목록
→ 그룹 선택
→ 해당 그룹의 오늘 Snap
```

### 그룹 생성·초대·멤버 관리

```text
그룹 탭
→ 그룹 생성
→ trim 후 1~30 grapheme cluster 이름 입력
→ 금액 공개 또는 비공개 선택
→ 생성 완료, 이후 공개 설정은 변경하지 않음
→ owner가 168시간 초대 발급
```

초대를 받은 인증 사용자는 가입 확정 전에 group name과 금액 공개 여부를 본다. 만료·폐기되었거나 정원이 찬 초대는 가입할 수 없다. 이미 member라면 재시도해도 같은 membership을 유지한다. group은 owner를 포함해 최대 20명이다.

member는 스스로 탈퇴할 수 있고 owner는 member를 내보낼 수 있다. owner는 MVP에서 role을 양도하거나 그룹을 탈퇴하지 않고 그룹 삭제를 선택한다. 그룹 삭제·탈퇴·제거는 개인 Snap을 지우지 않는다. owner 계정 탈퇴는 소유 그룹과 그 share를 삭제한 뒤 계정 cascade로 owner 자신의 개인 데이터를 삭제한다.

그룹 생성 또는 참여 시에는 해당 그룹의 금액 공개 설정을 확인한다. 공개 그룹은 가격까지 함께 공유하고, 비공개 그룹은 가격 텍스트 없이 소비 사진과 카테고리 중심으로 공유한다.

### 그룹 상세 Snap의 정보 우선순위

그룹 상세 Snap 화면의 주인공은 개별 소비 리스트가 아니라, 각 사람이 오늘 공유한 소비 흐름을 요약한 사람별 Snap 오브젝트다.

그룹 상세에서는 다음 순서를 우선한다.

1. 사람별 대표 Snap 오브젝트
2. 누가 올렸는지 알 수 있는 이름 또는 아바타
3. 해당 유저가 오늘 공유한 `sharedAt` 기준 최신 소비 이미지 또는 category placeholder
4. 해당 유저의 오늘 Snap 개수, 하단 정보 태그 안에 표시
5. 공개 그룹인 경우 해당 유저의 오늘 총액
6. 해당 유저의 오늘 Snap 상세로 들어가는 진입 액션

공개 그룹에서는 사람별 오브젝트 크기를 오늘 총액 기준으로 달리할 수 있다. 이때 크기 차이는 "누가 오늘 소비가 컸는지"를 직관적으로 보여주는 시각 언어다.

비공개 그룹에서는 사람별 오브젝트 크기를 총액 기준으로 달리하지 않는다. 금액 텍스트를 숨겨도 크기로 총액을 추정할 수 있다면 비공개 원칙이 약해지기 때문이다. 비공개 그룹은 동일 크기 또는 Snap 개수 중심의 가벼운 차이만 사용한다.

사람별 대표 Snap 오브젝트의 하단 정보 태그는 공개 설정에 맞는 금액, 이름, Snap 개수를 한 곳에 모아 보여준다. 좌상단은 이름 배지가 아니라 기본 avatar 자리로 사용한다. MVP에는 profile 사진 업로드가 없으므로 display name의 첫 grapheme 또는 MoneySnap mark를 보여준다. 사진 없는 대표 Snap은 category별로 고정된 icon과 color placeholder를 사용한다.

사람별 대표 Snap 오브젝트를 누르거나, 오브젝트 안의 화살표 액션을 누르면 해당 유저의 오늘 Snap 상세로 이동한다. 해당 상세 화면에서 그 유저가 오늘 올린 개별 Snap들을 세로로 볼 수 있다.

그룹 상세에 별도의 "오늘 올라온 Snap" 리스트를 중복으로 두지 않는다. 개별 Snap 목록은 사람별 상세에서 확인하게 하여, 그룹 상세는 사람별 요약 캔버스 역할에 집중한다.

## UX 판단 기준

- 기록 흐름은 사용자가 10초 안에 완료할 수 있어야 한다.
- 그룹이 없는 사용자는 공유 단계를 보지 않아야 한다.
- 그룹이 있는 사용자도 등록 흐름 안에서는 나만 보기 저장을 쉽게 끝낼 수 있어야 한다.
- 카테고리 선택과 가격 입력은 같은 바텀시트 안에서 단계적으로 전환되어야 한다.
- 기록 도중 금액 공개 여부를 매번 선택하게 만들지 않는다.
- 홈 스와이프는 빠른 확인, 그룹 탭은 그룹 목록과 진입 역할을 가진다.
- 그룹 상세에서는 개별 Snap 리스트보다 사람별 대표 Snap 요약을 먼저 보여준다.
- 저장 완료 후 캔버스 반영은 즉각적이어야 한다.
- 소비 기록은 가계부 작성보다 사진 스냅 저장에 가까워야 한다.
- 공유는 흐름의 중심이지만 기록보다 앞서 사용자를 멈추게 하면 안 된다.
